# AI-помощник для подготовки товарных описаний

Прототип сервиса для автоматической генерации черновиков карточек товаров контрольно-измерительных приборов для B2B-интернет-магазина с использованием LLM API.

Сервис принимает исходные характеристики товара в формате JSON, передаёт их языковой модели и формирует структурированный результат, который может использовать контент-менеджер для подготовки товарной страницы.

## Возможности

Для каждого товара сервис генерирует:

- **SEO-заголовок** — до 70 символов.
- **SEO-описание** — 800–1200 символов, если исходных данных достаточно.
- **Структурированные характеристики** — ключевые параметры товара.
- **Поисковые запросы** — от 3 до 5 вариантов.
- **Коммерческий блок** — целевая аудитория и задачи, для которых подходит прибор.
- **Информацию о недостающих данных** — какие характеристики требуют уточнения.
- **Предупреждения** — потенциально неподтверждённые числовые значения.

Если исходных данных недостаточно, сервис сообщает об этом и не пытается искусственно дополнять технические характеристики.

## Технологии

- Python 3.10+
- Groq API
- Модель `openai/gpt-oss-20b`
- Pydantic — проверка структуры и типов данных.
- python-dotenv — загрузка переменных окружения.

### Назначение основных файлов

| Файл | Назначение |
|---|---|
| `main.py` | Управляет обработкой входных файлов, запуском генерации и сохранением результатов. |
| `llm_client.py` | Отвечает за взаимодействие с Groq API. |
| `prompt_builder.py` | Загружает шаблон промпта и подставляет в него данные товара. |
| `product_card_prompt.txt` | Содержит инструкции для языковой модели по генерации карточки. |
| `models.py` | Определяет Pydantic-модели выходной карточки и её характеристик. |
| `validators.py` | Проверяет структуру ответа, ограничения SEO-полей и потенциально неподтверждённые числовые значения. |
| `display.py` | Отвечает за удобное форматирование и отображение готовой карточки в консоли. |
| `data/` | Содержит входные JSON-файлы с данными товаров. |
| `results/` | Содержит сгенерированные JSON-карточки. |

## Установка и настройка

### 1. Клонирование репозитория

```bash
git clone <ссылка-на-репозиторий>
cd product-card-generator
```

### 2. Создание виртуального окружения

```bash
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Если PowerShell блокирует запуск скриптов, можно разрешить их выполнение для текущего пользователя:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

После подтверждения повторно выполнить команду активации.

### 3. Установка зависимостей

```bash
python -m pip install -r requirements.txt
```

### 4. Настройка API-ключа

В корне проекта находится файл `.env.example` — пример конфигурации.

Создайте на его основе файл `.env`:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и укажите собственный API-ключ Groq:

```env
GROQ_API_KEY=your_api_key_here
GROQ_MODEL=openai/gpt-oss-20b
```

API-ключ можно получить после регистрации на [Groq Console](https://console.groq.com/).

**Важно:** файл `.env` содержит конфиденциальный API-ключ и добавлен в `.gitignore`. Его нельзя загружать в Git-репозиторий. Для запуска проекта каждый пользователь должен указать собственный ключ.

## Запуск проекта

Запуск выполняется из корневой папки проекта.

### Обработка одного товара

Чтобы сгенерировать карточку для конкретного товара, укажите имя JSON-файла из папки `data/`:

```bash
python -m src.main demo-001.json
```

### Обработка всех товаров

Для последовательной обработки всех JSON-файлов из папки `data/` используйте команду:

```bash
python -m src.main all
```

Сервис автоматически найдёт все JSON-файлы, обработает их по очереди и выведет итоговую статистику:

- количество успешно обработанных файлов;
- количество файлов с ошибками.

Ошибки при обработке одного товара не останавливают обработку остальных файлов.

## Результаты работы

Для каждого успешно обработанного товара сервис создаёт отдельный JSON-файл в папке `results/`.

Например:

```text
results/
├── demo-001_card.json
├── demo-002_card.json
├── demo-003_card.json
└── ...
```

Выходной JSON содержит следующие поля:

```json
{
  "seo_title": "SEO-заголовок товара",
  "seo_description": "SEO-описание товара",
  "characteristics": [
    {
      "name": "Диапазон измерений",
      "value": "0–600 В"
    }
  ],
  "search_queries": [
    "цифровой мультиметр",
    "мультиметр для измерения напряжения",
    "купить цифровой мультиметр"
  ],
  "commercial_block": "Описание целевой аудитории и задач прибора.",
  "missing_information": [],
  "warnings": [],
  "needs_more_data": false
}
```

Это пример структуры результата, а не реальные характеристики конкретного товара.

### Просмотр результата в консоли

Для удобства просмотра реализована функция `print_card()` в `src/display.py`.

Она выводит содержимое карточки в структурированном виде и автоматически переносит длинные строки на новую строку с использованием `textwrap`.

Ширина вывода по умолчанию — 80 символов.

Функция отображает:

- SEO-заголовок;
- SEO-описание;
- характеристики;
- поисковые запросы;
- коммерческий блок;
- недостающую информацию;
- предупреждения.

После успешной генерации карточка автоматически выводится в консоль.

При этом исходное содержимое JSON не изменяется: форматирование применяется только при отображении.

Чтобы посмотреть результат отдельно, достаточно открыть соответствующий JSON-файл из папки `results/`. Для повторного красивого вывода можно использовать `print_card()` в коде, передав ей объект `ProductCard`.

## Принятые решения

### 1. Выбор LLM

Для генерации используется Groq API с моделью `openai/gpt-oss-20b`.

Взаимодействие с API вынесено в отдельный модуль `llm_client.py`, что позволяет при необходимости заменить провайдера или модель без изменения основной логики приложения.

### 2. Формирование промпта

Инструкции для модели вынесены в отдельный текстовый файл `prompts/product_card_prompt.txt`.

Это позволяет изменять правила генерации без редактирования Python-кода.

Промпт содержит следующие основные требования:

- использовать только сведения из исходного JSON;
- не придумывать технические характеристики;
- не добавлять неподтверждённые преимущества и свойства;
- соблюдать ограничения длины SEO-полей;
- явно сообщать о недостатке исходной информации;
- возвращать результат в формате JSON.

### 3. Структурирование результата

Для описания выходной карточки используются Pydantic-модели.

Это позволяет проверять наличие обязательных полей и соответствие ожидаемым типам данных.

### 4. Валидация

После получения ответа от модели выполняются проверки:

- корректность JSON и соответствие Pydantic-модели;
- длина SEO-заголовка;
- длина SEO-описания, если исходных данных достаточно;
- наличие числовых значений в исходных данных, на которые ссылаются характеристики.

Последняя проверка является эвристической: она помогает обнаружить некоторые потенциально неподтверждённые значения, но не гарантирует полную проверку фактической достоверности.

### 5. Обработка ошибок

Предусмотрена обработка ошибок чтения и разбора входных JSON-файлов, ошибок API, пустых ответов модели и некорректной структуры сгенерированного результата.

При пакетной обработке ошибка одного товара не прерывает работу со следующими файлами.

## Ограничения и возможные улучшения

Текущая реализация представляет собой MVP и имеет ряд ограничений:

1. **Проверка фактической достоверности.** Наличие числа в исходном JSON не гарантирует, что оно использовано в правильной характеристике. Для более строгой проверки потребуется сопоставление конкретных полей и значений.
2. **Качество генерации.** Несмотря на подробные инструкции, модель может нарушать ограничения длины или использовать неподтверждённые формулировки. Поэтому результат требует проверки человеком.
3. **Повторная генерация.** При нарушении ограничений можно добавить автоматическую повторную генерацию с указанием конкретной ошибки валидации.
4. **Поддержка входных форматов.** В дальнейшем можно добавить загрузку Excel-файлов и простую веб-форму.
5. **Тестирование.** Можно расширить набор автоматических тестов для проверки промпта, валидатора и обработки различных входных данных.

## Итог

Реализован локальный прототип AI-помощника, который автоматизирует подготовку черновиков товарных карточек контрольно-измерительных приборов.

Сервис поддерживает обработку одного товара или целой папки JSON-файлов, сохраняет результаты в структурированном формате и предоставляет удобный вывод карточки в консоли.

Результат предназначен для дальнейшей проверки и редактирования контент-менеджером перед публикацией в интернет-магазине.
